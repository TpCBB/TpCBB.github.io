自己做了一个 AI 面试练习工具：聊聊我怎么用 AI 辅助开发，以及手搓 SSE 流式输出

发表于 2026-11-17 | 分类于 AI 与工具 |
记录如何指挥 AI 帮我把一个 171 题的前端面试练习工具工程化落地。重点拆解：在严苛的 JSON 结构下，如何手搓流式 SSE 增量解析、未闭合转义容错以及字素级打字机效果。

之前整理了 171 道前端与全栈核心面试题（从 Vue3 响应式、Koa2 中间件内核，到微前端隔离和工程化链路）。为了让自己能真正开口练，我用 Next.js + 本地 MySQL 做了个专属的面试模拟练习工具（Interview Coach）。

核心玩法简单粗暴：我答题，AI 扮演毒舌面试官挑刺打分；答得不好打回重答，答得好当场追问，直到真正理解掌握。

这篇文章聊两个最硬核的话题：

  1. 怎么跟 AI 配合开发：很多人用 AI 写代码越写越乱，我是怎么给它定规矩、让它老老实实写出生产级代码的；
  2. 重点拆解 SSE 流式输出：既要让 AI 吐出严格的 JSON 结构，又要实现打字机般的流式渐进展示，这套底层逻辑是怎么手搓出来的。

1. 怎么指挥 AI 写出高水准代码？

现在很多人觉得“用 AI 写代码不就是开盲盒吗？改着改着就炸了”。

其实关键在于：AI 是打工的架构执行者，你必须是定死技术规范的架构师。如果只给一句“帮我写个面试打分页面”，它写出来的代码大概率是单文件塞满几千行、全是 any、状态随手抓瞎。

在这次开发中，我对 AI 的约束很明确：

  • 立死规矩（AGENTS.md）：TypeScript 必须开 strict: true，关掉 allowJs，整个项目零 any；所有数据边界（表单、API 请求、大模型输出）必须经由 Zod 双向强校验。
  • 职责分层卡死：页面组件只负责搭骨架，业务逻辑拆到 features/，接口缓存归 RTK Query，交互状态归 Redux Slice。AI 只要敢把 MediaStream 这种不可序列化的对象往 Redux 里塞，或者把 API Key 存进前端 store，当场打回重写。
  • 让测试成为紧箍咒：写完功能不是“看着能跑就行”，必须配套写自动化测试。这次我们跑了 24 项全套集成测试——包括真实启动 Next.js 独立端口跑 HTTP 请求、验证分段流式输出、模拟客户端断开测试后端是否及时掐断。

有了这套严丝合缝的规矩，AI 写起代码来就极其顺手：它负责填充具体的高质量算法与工具函数，我负责盯死边界与工程质量。

2. 重点攻坚：手搓 SSE 流式增量解析

整个项目里最具挑战性的技术点，就是大模型的流式评估（Streaming Feedback）。

2.1 鱼与熊掌的矛盾：结构化 JSON vs 流式打字机

用过大模型 API 的人都知道这个两难困境：

  1. 要严谨评分：我们必须要求大模型输出 JSON 格式。因为评分系统需要结构化提取：考点通过情况、最大短板、示范答案、追问题目、分数。如果只让模型自由发挥吐 Markdown，很难稳定解析出精确数据。
  2. 要极致体验：如果等模型把 500 字的 JSON 全部生成完再展示，用户要在屏幕前死等 5 到 10 秒；最好的交互必须是 SSE（Server-Sent Events），像打字机一样一个字一个字往外蹦。

但问题来了：在流传输的过程中，整个 JSON 字符串从头到尾都是“残缺不全”的！
普通的 JSON.parse() 只要碰到一个没闭合的引号或花括号，立刻当场抛语法错误（SyntaxError）。

难道只能等整段流结束再展示？当然不。

2.3 字素感知（Grapheme）：让流式光标不再抽搐

在打字机渲染时，文本末尾通常有一个跟随闪烁的呼吸光标。

如果直接用 text.slice(0, len) 这种传统字符串截取方式，在遇到中文组合、Emoji 表情（例如 👩‍💻）或者 Unicode 音调字符时，光标定位会直接把字符“腰斩”，造成页面闪烁和控制台乱码。

2.4 双向 Abort：绝不白白浪费 Token

在流式输出中，如果用户看到一半发现自己答跑题了，点击了“停止生成”或者直接点了下一题，普通的做法只是把前端页面给停了，但后端的模型接口还在吭哧吭哧生成。

这对于按 Token 付费的调用来说就是真金白银的浪费。

3. 业务闭环与状态分层

有了底层的流式通道，上层的做题逻辑才能真正立得住：

  • 拒绝无脑及格：只有主问题得分 ≥ 8 分、考点全通过，才会触发针对薄弱项的追问；追问答对了才算真正掌握，自动挂载艾宾浩斯记忆遗忘曲线（1, 3, 7, 14, 30 天）进入复习池。
  • 数据清晰隔离：
    • 题库进度和掌握状态归 RTK Query 缓存，单向权威；
    • 题目切换和全局操作锁归 Redux Slice，在打分和录音时把提交按钮同步锁死，杜绝并发连击；
    • 答题草稿和卡片折叠习惯归 sessionStorage，刷新网页草稿依然在；
    • API Key 直接落本地文件（0600 权限），绝不流入浏览器前端。

4. 总结

现在的 AI 已经有极强的代码编写能力，但如果你只让它写个“Demo”，它就真的只给你一个漏风的 Demo。

让 AI 产出高质量项目的关键，就是用硬核的工程约束（Strict TypeScript + 规范架构 + 自动化测试）去框定边界，用精细的技术方案（手搓流式状态机 + 双向连接控制）去攻克体验瓶颈。

把这套组合拳打下来，不仅代码清爽扎实，自己刷起题来也是真的爽。
